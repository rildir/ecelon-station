# Changelog

## [Unreleased]

- **The demo is a small fictional ERP.** Eight project rooms instead of three, one per module of a made-up company (stock, sales, purchasing, finance, production, payroll, e-invoice, field): every room has its own small code base with passing tests, and the stock room carries the analysis document, which is also shipped in Turkish and picked by the station language (project names are Turkish too with `--lang tr`). The office lays out eight rooms as a diamond without any layout change. The sample projects are listed in `demo/projects.json`.
- **The demo, walked end to end on a laptop screen.** The tour opens the conversation of the member that is working, so the document being read, the scope being saved and the tests being run are visible as they happen. Its last card stays until you close it and offers "Give the team a job", which puts an example request in the message box. That request makes a real change in the sample project (a `GET /inventory/low` route built on the model's own function; the change card and the Git screen show code, not a comment line), then asks before `git push`; after the permission only the refused step is repeated instead of the whole job. The analyst and the tester no longer raise a `git push` request of their own, and what they cannot settle goes to the task board: a decision for you, a missing piece for the developer. A task started from the board is closed there when the work is done. "Start up" in the demo plans from the project's own files and only imitates the start (nothing is launched); in a real station a plan guessed from the project files is offered when the model cannot be asked.
- **The station's own tools read as what they do.** In a conversation the team tools are named by their job, with the item they touch ("Scope R-002 · doing", "Verification R-001 · verified", "New task …"), instead of `mcp__team__…`. A permission card that was answered from the approval queue or a notification says "Allowed" instead of still asking.
- **Fixed on a 1366×768 screen.** The Scope header is two rows (title, search and the proof report; the steps below) instead of a crushed search box. The top bar keeps to one row with the panel open: the button labels go first, the usage meter later. The model name and the team strip of the message box are no longer cut to "Sonn…" and "I…". "Send to all" fits without scrolling, and a dialog that is still taller than the window keeps its buttons in view. In the professional view the active filter chip, a busy member tile and the hovered "Open" were white on white. The approval queue remembers whether it is open per view, so switching views no longer leaves it open on top of the project list.
- **The office after dark.** The evening light was blue-violet, which turned the graphite rooms lavender every night; night is now a dimmer neutral light. The rose room accent became wine and the violet one olive, and the "new" label on an unread project uses the accent instead of cyan.
- **A polish pass over the inner screens.** The Scope header shows its four steps (extract, compare, verify, second opinion) as one numbered control, with the side actions quiet and the proof report as the single main action. The demo offer no longer sits on top of full-screen sections. The project toolbar stays on one line in a narrow panel. Empty states share one shape (icon, title, what to do). The editor and the Run output are black like the rest, the "document changed" alerts use the amber accent instead of violet, and the selection ring in the office is white. JS Study is parked: its button is hidden unless switched on with `?study=1`.
- **The office view in one visual language.** Rooms are neutral graphite with the kit's amber trim (the lavender and navy of the space kit are repainted once, in memory); every room shares one calm furniture base and differs by a single muted accent. Reply bubbles and the message box are dark like the rest of the page, the hazard stripes on the panel, dialogs and full-screen sections are gone, the stage is black at every hour, a selected room has a white name plate instead of a blue one, and a small dot before a room's name shows what it is doing (working, done, error).
- **Long sessions stay fast.** Typing no longer slows down as a conversation grows: the message box is laid out on its own and resized only when its line count changes (before, every key laid out the whole conversation). A run that goes on for an hour keeps the page bounded: with more than 650 messages drawn and you at the bottom, the oldest are dropped from the page (not from the history; "Show earlier messages" brings them back). The once-a-second activity strip no longer lays out the conversation, and background polls (git status of every project, overview, payroll, sessions) rest while the window is hidden and catch up when you return.
- **Start a project with one click.** A project has a "Start up" button at the top right of its header. The first click asks a small model (Haiku) once how the project starts, from a short digest of the projects on the station: start scripts, ports in angular.json / project.json / launchSettings.json / server files, local addresses in proxy and environment files (never .env files or connection strings). It suggests the steps, dependencies first (for example the backend a frontend calls); you check and edit the commands before anything runs, and the plan is saved. Later clicks use the saved plan with no model: each step starts in the Run panel and the next waits until its port answers; a step already running is left alone. The button turns amber while starting, green when everything answers, red with the reason when a step fails; its menu stops what it started, shows the output or edits the plan.
- **Usage panel: account and fallback model.** The usage panel names limits that belong to one model ("Weekly Fable limit"), shows who is signed in (from `claude auth status`) and has a switch that passes `--fallback-model` (Sonnet 5.5) to Claude Code, so a message is answered by another model when the chosen one is busy or unavailable.
- **Fixed: one-off questions to Claude Code failed on newer versions** (the JS Study tutor, the suggested commit message) with "Denying Bash also turns off the PowerShell tool" / "MultiEdit matches no known tool". They now run with no tools at all (`--tools ""`), and ask once more without that switch on a Claude Code that does not know it.
- **JS Study: a problem set.** Practice has a fourth place, Problems: a function to write, from easy to hard, judged by test calls that run in the sandbox. Every call shows what was expected and what your code gave (or the error it threw); your own console output is shown beside it, and a loop that never ends is cut after three seconds. Hints open one by one, the tutor gives a nudge but not the answer (and the complexity once it is solved), and the explanation and a reference solution open when your own code passes. Packs take a `problems` list; Today offers the next unsolved one.
- **JS Study: a lesson asks before it moves on.** The next step opens after the code of the current one has been run, and, where the step has a question, after it has been answered (the answer shows which option was right and why). "Show all steps" still opens everything at once. Packs may give a step a `check`.
- **A black theme.** The navy and lilac tint is gone from both views: the background is black, surfaces are near-black, text is grey. The professional view is black and white (no cobalt): the accent is white, and colour is kept for status only. The office view keeps its amber accent on the same black. The large filled project tile is now a quiet tint with an accent line. The editor, the terminal and the window frame follow.
- **JS Study: a room you can find your way in.** It opens on **Today**: one suggested next step (the warm-up when something is due, the lesson you left half-way, or the next unread lesson) with what else is open, your numbers and the path at a glance. **Learn** is the path itself, with what you have read. **Practice** holds quiz, say it and code; **Notes** the cheat sheet. A lesson now opens its steps one after another and remembers where you stopped; the code in a step can be changed and run (Tab indents, Ctrl+Enter runs). The tutor's answer can be questioned further, shows the seconds while it thinks and can be given up. Views fade in, and each keeps its scroll position.
- **JS Study: a tutor, and lessons you read step by step.** A lesson opens as a page of its own: small steps that each build on the one before, every one with code you can run, then the points, a mistake to avoid, and what to practise next. Four things can be asked of a tutor (Claude Code, one question at a time, without tools): explain why the option I chose was wrong, grade the answer I wrote in my own words, comment on my code for a task (a hint when it is wrong, a review when it is right), and write new questions for a topic. A question the tutor writes is run in the sandbox and kept only when its real output is one of its options; the right option is set from that output.
- **JS Study: topic pages, "Say it" and a full JavaScript pack.** A topic now opens as a short lesson: a summary, the points to know, an example you can run, a common mistake, its own cheat sentences and how to say it aloud. Topics are grouped and ordered as a learning path, and the map names the next topic to learn. A new "Say it" tab asks open questions: answer in your own words, open the model answer, mark whether you had it (unseen and missed questions come first). Packs may carry `group` and `lesson` per topic (all optional, old packs still import). The pack itself is data you import; it is not part of the repository.
- **JS Study.** A personal study room for JavaScript, next to the Playground in the top bar. A map of topics whose state (settled, getting there, weak, new, review due) is worked out from your answers; click-through quizzes (a daily warm-up that starts with yesterday's mistakes, a quiz on one topic, a mixed quiz) with the options shuffled every time and the topic hidden until you have answered; coding tasks that run in the same sandbox as the Playground (3-second limit, timers and promises are waited for) and ask for your guess before you run; a cheat sheet with your own notes; content packs you import as JSON (a pack with an error changes nothing). The progress is kept in `data/study.json` on your computer and is never committed.

## [0.2.0] - 2026-11-13

- **Tasks on their own branches.** "On its own branch" on the task board runs a task in a separate git worktree (in the station's data folder, never inside the project) with its own agent and chat, so several tasks can run on one project at the same time. The card shows what the branch changed; Review shows the diff; Merge commits what is left and merges it into the project's current branch; Discard removes the copy and the branch. A conflicting merge is aborted, so the working copy is never left half-merged, and the branch is kept.
- **Demo data apart.** `--demo` keeps its sample projects in a folder of its own (`data-demo` from a clone, `~/.ecelon-station-demo` when installed), so trying the demo never mixes fake agents into real projects.
- **README** rewritten around the proof chain, with a comparison table and new screenshots of the professional view.
- **The server can restart itself, and says when it has to.** The server is one long-lived process: closing the window does not stop it, and the shortcut leaves a running one alone. After an update the page was new and the process old — missing features, half-translated texts. The server now notices that its own files changed since it started and the page shows it, with a "Restart the server" button (refused while agents are working). A page that finds a server from before this change says how to stop it by hand. Translations are also re-read when their file changes.
- **Playground.** A JavaScript scratch pad in the top bar: the same editor as the code view, Run (Ctrl+Enter) and a console with `log`/`warn`/`error`/`table`, top-level `await`, and a "line N" button on errors that jumps to the line. The code runs in a worker inside a sandboxed frame with its own origin — it cannot reach the station's API or storage, and an endless loop is stopped after three seconds instead of freezing the window. A file can also be a **web page**: HTML, CSS and JS tabs with a live preview (HTML and CSS refresh as you type, JS on Run), its console below, and a loop guard so an endless loop in the page stops after two seconds. The output can sit next to the editor or below it, and the line between them can be dragged (double-click resets it). A status bar under the editor shows the line, column, language and text size; Ctrl + mouse wheel, Ctrl +/- and the − / + buttons change the size (remembered; click the size to reset). Files are kept in the browser. "Ask for a hint" opens a free chat with the code and a request for a hint rather than the solution.
- **Desktop app (Windows).** An Electron shell around the same local server: its own window, icon and taskbar identity, no browser menu or developer tools (`--dev` brings them back), external links open in the default browser, and a tray icon keeps agents working after the window is closed. Quit stops the server the app started (and asks first if agents are working); a server that was already running is left alone. `npm run desktop` runs it from a clone; `npm run dist` builds the installer and the portable exe; pushing a `v*` tag publishes them on a GitHub release with Node bundled. Not code-signed.
- The station no longer needs WebGL to start: without it (remote desktops, virtual machines) it runs in the professional view only instead of showing a broken page.
- **App window.** Opened from the launcher (or installed as an app), the station behaves like a desktop program: the browser's developer shortcuts (F12 and friends) and its right-click menu stay out of the way; text fields keep their menu. `?dev=1` switches this off for the session. It is tidiness, not protection — the server never trusts the page.
- Fixed: the paperclip (attach) button was missing in project chats and "Turn into a project" opened the attach menu — two buttons shared one id.
- Long names and small windows: dialogs taller than the window scroll inside themselves (Send to all lost its buttons at 768px); a long project name no longer pushes the task filters and actions off screen; long unbroken task titles wrap; the effort and permission pills keep their word in a narrow panel; a free chat no longer suggests initializing git; in the professional view the approval list starts folded.
- Model list: Fable 5.2 is the featured Fable; 5.1 moved under other models.
- **Free chats.** "New chat" opens one assistant without a project or a team — for a question, a draft, a file to look at. Chats are listed apart from the projects (newest first, named after the first message) in both views, and have no room in the office. "Turn into a project" gives a chat a folder: it becomes a project with a full team; what was said stays on screen, the team starts a new session. Each chat row has rename and delete on hover; deleting a chat removes its transcript and scratch folder too. A chat lives in the station only; conversations that an earlier version copied from Claude Code sessions into projects can be taken back in one click. `POST /api/chats`, `POST /api/chats/:id/attach`.
- Professional view: the roster has a second layout, **Mosaic**. Every project is a block that fills from the bottom with what has been proven: solid is verified with evidence, hatched is what the document calls done without proof, empty is what is left. The bigger the scope, the bigger the block; linked projects sit side by side; the four pips are the roles, and a block that waits for you gets an amber edge and says who is waiting. The levels rise once when the mosaic is first opened. List stays the default.
- Professional view, every screen: no character pictures anywhere (library, link lists, notifications, palette — wherever a member's picture was set, the mark is shown), documents are read on a dark sheet, and the remaining rounded containers and pressed shadows are gone. Checked by an automatic sweep over the home, conversation, library, Scope, tasks, git, code, runs, history, audit, links, add-project, notifications, send-to-all, usage and quick-switch screens.
- Professional view, second pass: the project list is no longer shown twice — the roster is the list, and the panel appears only with the conversation you open; projects with nothing going on are one line, the ones at work or waiting for you show their roles; every block says what it opens (conversation, Scope, task board); no dollar figures anywhere in this view (runs and agent hours instead), and the proof report leaves cost out unless asked (`?cost=1`).
- **Costs were overstated, in some projects many times over.** Claude Code reports the cost of the whole session so far with every run; the payroll, the cost per requirement, the proof report and the notifications added those running totals up as if each were one run. A run now costs the step from the previous figure, and new runs store that figure in the log.
- Professional view, completed: the conversation, the composer, the approval queue, toasts, tabs and dialogs are dark and flat too (no light bubbles, no hard shadows, no pill shapes, quiet badges); two roles that share an initial get two letters on the roster.
- Static files are always revalidated, so after an update the page can no longer run new code with old translations.
- **Professional view.** A second face for the same station, switched from the top bar (or `?view=pro`) and remembered per browser: no 3D scene, no characters, no sound, no screensaver. Graphite and cobalt, hairlines, numbers in mono. The stage becomes a roster: every project with what each role is doing right now, its evidence bar (verified / failed / needs re-verification / not verified), tasks and the week's cost; whatever waits for you comes first. The whole app (panel, dialogs, Scope, notifications) follows the same look. The office view is unchanged and one click away.
- The log digests kept in memory are bounded (least recently used go first), so making proof reports for a project with many long conversations cannot grow the server's memory without limit.
- **Audit trail.** Every command an agent runs, every file it writes, every permission you grant (once or always), every refusal, permission-mode change, verification, undo and project add/remove is appended to `data/audit.jsonl`. Each entry carries the hash of the one before it, so a changed or removed line shows as a broken chain. Project menu (⋯) → Audit trail: filter by kind, one project or all, chain check, CSV export (formula-safe). `GET /api/audit`, `GET /api/audit.csv`.
- **Proof report.** Scope → Proof report opens one self-contained page with the whole evidence chain of the project: for every requirement what the document says, the code lines the evidence points at, how it was verified, by whom and when, and what the work cost. Evidence is re-checked when the report is made and the page carries the branch and commit. No scripts or external files; prints cleanly. `GET /api/reqs/:team/report` (`?download=1` to save).
- **The demo plays itself.** In demo mode the station offers a one-minute tour: the sample team extracts the requirements, compares them with the code, verifies with evidence and ends on the mismatch and the proof report.
- The "new" badge in the project list was Turkish in every language; it is translated now.
- The scene uses `THREE.Timer` (the clock it used is deprecated in three 0.18x).
- Smoothness: opening a long conversation no longer measures the page once per message (the main cause of the hitch when switching projects); the payroll and replay data are digested once per log and then only the new lines are read, so the server no longer stalls every live stream for a moment every two minutes; the project list is re-read from disk only when it changed; a long live session cuts the chat back to its tail when a run ends.
- Layout at the default window size: the top bar no longer slides under the panel, and the project buttons stay on one row.
- **Notification centre.** The bell opens a real panel instead of a short menu: a one-line digest of today, a 24-hour strip with one tick per notification (click a tick to jump to it), a pinned "Waiting for you" block where a permission can be granted in place, filters by kind and by project, days as sticky headings, repeated permission requests folded into one row with a count, portraits, steps · duration · cost per finished job, read/unread and remove per row, arrow-key navigation. History grows from 40 to 200 entries.
- Notification text is now the first sentence of the member's final reply instead of a slice from the middle of it.
- Wall layout: the whiteboard, payroll board, posters, printer and boxes no longer sit over the passages to neighbouring rooms; boards are flush with the wall.
- The office shows the real state of each project: papers pile up on the lead's desk with uncommitted changes, boxes wait by the door for unpushed commits, the plant grows with verified scope (and wilts on a failed verification or error), the whiteboard carries the task board as sticky notes, the printer has today's report.
- Everything in the room is a button: whiteboard → tasks, papers/boxes → git, plant → scope, bookcases → documents, server rack → run, printer → copyable daily report, coffee machine → stop the room for a break.
- Hand-offs in the room: when the lead gives a member a task, the lead walks to that member's desk with a document over its head; the member brings the result back the same way.
- Test runs light the beacon on the room's server rack: amber while tests run, a flashing red alarm and a red floor when they fail, green and confetti when they pass (npm/pnpm/yarn test, jest, vitest, pytest, dotnet test, nx test, go test, cargo test and more).
- Live screens: the monitors on the desks show what each member is really doing (the file being written with highlighted code, the command being run and its output, green OK / red FAILED). Click a monitor to lean in: the camera goes to the desk and a readable copy of the screen opens in the corner.
- Day and night: the office follows your clock; sunset light in the evening, at night the lamps come on and the screens of members still at work glow.
- Morning stand-up: the first time you open the station in a day (or with the sun button by the zoom controls) the camera tours the rooms; each team gathers at its meeting table while a card shows yesterday, today and blockers. Esc skips, → goes to the next room.
- Neglect shows: tasks left untouched for 3+ days, stale verifications, mismatches and a huge pile of uncommitted changes bring crumpled paper on the floor and cobwebs on the walls; tidy up and the room is clean again. The cobweb is a button too (→ tasks).
- The office cat: one cat for the whole station goes where you are needed (a member waiting for permission, a room whose tests broke, an error), sits next to that member with a "!" and naps on a rug ("zZ") when all is calm. Click it to go there.
- Drop files onto the office: a picture onto a character is attached to a message for that member; a document dropped onto a room is added to the library, linked to that project and attached to the message.
- The TV replays the day: click the TV in a room's lounge and today's work in that room plays back in ~40 seconds (who worked when, hand-offs, files written on the screens, test runs lighting the beacon), with a clock, red/green marks for failed and finished runs, pause and 1×/2×/4× speed. Built from the existing conversation logs; nothing new is recorded.
- Speech bubbles: when a member finishes a reply, its first sentence appears over its head for a few seconds, comic style.
- Office sounds (off by default, speaker button at the top): synthesized in the browser, no audio files. A soft bell when a run finishes, a low buzzer when tests fail, a rising arpeggio when they pass, a ping when someone waits for permission, a paper rustle on hand-offs and quiet keyboard ticks while the team you are looking at writes.
- Payroll on the wall: a board above the reviewer's desk shows what each member cost this week (Monday onwards). Click it for the payslip and the cost per requirement item: a run's cost is split between the items it named, set or verified (R-046: $4.10, 2 runs, developer + tester).
- Posters on the back wall say what the project is built with (Angular, .NET, Godot, React Native, Node, PHP, Python, Docker…), detected from the project folder. Plain original designs, no logos.
- Broadcast: one button (camera icon by the zoom controls) turns the station into a live feed for a second screen. The interface steps aside, the camera glides by itself to whatever happens (a hand-off, a test run, a permission request, a run finishing or failing) with a lower third saying what it is, and in calm moments drifts from one busy room to the next. Record saves a 20 s clip of the 3D view as .webm, the camera button a picture. Esc leaves.
- Screensaver: left alone for four minutes with no conversation open, the station goes on air by itself (the broadcast above) and comes back at the first touch of the mouse or keyboard.
- Approval queue: an agent waiting for permission walks to the door with a "!" over its head; grant it (once or always) from the queue on the stage without opening the chat.
- Task board: agents leave a task for another role (or for you) instead of stopping at "I cannot do that"; start it with one click, track it in To do / In progress / Blocked / Done.
- Chat: team status strip, pinned last prompt; editor font zoom (Ctrl + wheel).
- Fixes: queued messages could get stuck after the agent finished; server restarts no longer silently cut agents off; notification panel overflow.

## 0.1.0 — first public release

- Isometric station: every project folder is a room, every role (developer, analyst, tester, reviewer) a character.
- Team workflow with hand-offs; only the developer writes files.
- Scope: requirements extracted from linked analysis documents, compared with code, verified by the tester with real evidence.
- Document coverage: every paragraph / item / row / heading / image tracked; "contains no requirement" needs your approval.
- Git checkpoints, change cards with diffs and one-click undo.
- Document library with version history, search, optional MarkItDown reader.
- English and Turkish UI.
- `npm run demo`: scripted demo agents on three sample projects, no Claude Code required.
