# Changelog

## Unreleased

- **Free chats.** "New chat" opens one assistant without a project or a team — for a question, a draft, a file to look at. Chats are listed apart from the projects (newest first, named after the first message) in both views, and have no room in the office. "Turn into a project" gives a chat a folder: it becomes a project with a full team; what was said stays on screen, the team starts a new session. `POST /api/chats`, `POST /api/chats/:id/attach`.
- Professional view: the roster has a second layout, **Mosaic**. Every project is a block that fills from the bottom with what has been proven: solid is verified with evidence, hatched is what the document calls done without proof, empty is what is left. The bigger the scope, the bigger the block; linked projects sit side by side; the four pips are the roles, and a block that waits for you gets an amber edge and says who is waiting. The levels rise once when the mosaic is first opened. List stays the default.
- Professional view, every screen: no character pictures anywhere (library, link lists, notifications, palette — wherever a member's picture was set, the mark is shown), documents are read on a dark sheet, and the remaining rounded containers and pressed shadows are gone. Checked by an automatic sweep over the home, conversation, library, Scope, tasks, git, code, runs, history, audit, links, add-project, notifications, send-to-all, usage and quick-switch screens.
- Professional view, second pass: the project list is no longer shown twice — the roster is the list, and the panel appears only with the conversation you open; projects with nothing going on are one line, the ones at work or waiting for you show their roles; every block says what it opens (conversation, Scope, task board); no dollar figures anywhere in this view (runs and agent hours instead), and the proof report leaves cost out unless asked (`?cost=1`).
- **Costs were overstated, in some projects many times over.** Claude Code reports the cost of the whole session so far with every run; the payroll, the cost per requirement, the proof report and the notifications added those running totals up as if each were one run. A run now costs the step from the previous figure, and new runs store that figure in the log.
- Professional view, completed: the conversation, the composer, the approval queue, toasts, tabs and dialogs are dark and flat too (no light bubbles, no hard shadows, no pill shapes, quiet badges); two roles that share an initial get two letters on the roster.
- Static files are always revalidated, so after an update the page can no longer run new code with old translations.
- **Professional view.** A second face for the same station, switched from the top bar (or `?view=pro`) and remembered per browser: no 3D scene, no characters, no sound, no screensaver. Graphite and cobalt, hairlines, numbers in mono. The stage becomes a roster: every project with what each role is doing right now, its evidence bar (verified / failed / needs re-verification / not verified), tasks and the week's cost; whatever waits for you comes first. The whole app (panel, dialogs, Scope, notifications) follows the same look. The office view is unchanged and one click away.
- The log digests kept in memory are bounded (least recently used go first), so making proof reports for a project with many long conversations cannot grow the server's memory without limit.
- **Audit trail.** Every command an agent runs, every file it writes, every permission you grant (once or always), every refusal, permission-mode change, verification, undo and project add/remove is appended to `data/audit.jsonl`. Each entry carries the hash of the one before it, so a changed or removed line shows as a broken chain. Project menu (⋯) → Audit trail: filter by kind, one project or all, chain check, CSV export (formula-safe). `GET /api/audit`, `GET /api/audit.csv`.
- **Proof report.** Scope → Proof report opens one self-contained page with the whole evidence chain of the project: for every requirement what the document says, the code lines the evidence points at, how it was verified, by whom and when, and what the work cost. Evidence is re-checked when the report is made and the page carries the branch and commit. No scripts or external files; prints cleanly. `GET /api/reqs/:team/report` (`?download=1` to save).
- **The demo plays itself.** In demo mode the station offers a one-minute tour: the sample team extracts the requirements, compares them with the code, verifies with evidence and ends on the mismatch and the proof report.
- The "new" badge in the project list was Turkish in every language; it is translated now.
- The scene uses `THREE.Timer` (the clock it used is deprecated in three 0.18x).
- Smoothness: opening a long conversation no longer measures the page once per message (the main cause of the hitch when switching projects); the payroll and replay data are digested once per log and then only the new lines are read, so the server no longer stalls every live stream for a moment every two minutes; the project list is re-read from disk only when it changed; a long live session cuts the chat back to its tail when a run ends.
- Layout at the default window size: the top bar no longer slides under the panel, and the project buttons stay on one row.
- **Notification centre.** The bell opens a real panel instead of a short menu: a one-line digest of today, a 24-hour strip with one tick per notification (click a tick to jump to it), a pinned "Waiting for you" block where a permission can be granted in place, filters by kind and by project, days as sticky headings, repeated permission requests folded into one row with a count, portraits, steps · duration · cost per finished job, read/unread and remove per row, arrow-key navigation. History grows from 40 to 200 entries.
- Notification text is now the first sentence of the member's final reply instead of a slice from the middle of it.
- Wall layout: the whiteboard, payroll board, posters, printer and boxes no longer sit over the passages to neighbouring rooms; boards are flush with the wall.
- The office shows the real state of each project: papers pile up on the lead's desk with uncommitted changes, boxes wait by the door for unpushed commits, the plant grows with verified scope (and wilts on a failed verification or error), the whiteboard carries the task board as sticky notes, the printer has today's report.
- Everything in the room is a button: whiteboard → tasks, papers/boxes → git, plant → scope, bookcases → documents, server rack → run, printer → copyable daily report, coffee machine → stop the room for a break.
- Hand-offs in the room: when the lead gives a member a task, the lead walks to that member's desk with a document over its head; the member brings the result back the same way.
- Test runs light the beacon on the room's server rack: amber while tests run, a flashing red alarm and a red floor when they fail, green and confetti when they pass (npm/pnpm/yarn test, jest, vitest, pytest, dotnet test, nx test, go test, cargo test and more).
- Live screens: the monitors on the desks show what each member is really doing (the file being written with highlighted code, the command being run and its output, green OK / red FAILED). Click a monitor to lean in: the camera goes to the desk and a readable copy of the screen opens in the corner.
- Day and night: the office follows your clock; sunset light in the evening, at night the lamps come on and the screens of members still at work glow.
- Morning stand-up: the first time you open the station in a day (or with the sun button by the zoom controls) the camera tours the rooms; each team gathers at its meeting table while a card shows yesterday, today and blockers. Esc skips, → goes to the next room.
- Neglect shows: tasks left untouched for 3+ days, stale verifications, mismatches and a huge pile of uncommitted changes bring crumpled paper on the floor and cobwebs on the walls; tidy up and the room is clean again. The cobweb is a button too (→ tasks).
- The office cat: one cat for the whole station goes where you are needed (a member waiting for permission, a room whose tests broke, an error), sits next to that member with a "!" and naps on a rug ("zZ") when all is calm. Click it to go there.
- Drop files onto the office: a picture onto a character is attached to a message for that member; a document dropped onto a room is added to the library, linked to that project and attached to the message.
- The TV replays the day: click the TV in a room's lounge and today's work in that room plays back in ~40 seconds (who worked when, hand-offs, files written on the screens, test runs lighting the beacon), with a clock, red/green marks for failed and finished runs, pause and 1×/2×/4× speed. Built from the existing conversation logs; nothing new is recorded.
- Speech bubbles: when a member finishes a reply, its first sentence appears over its head for a few seconds, comic style.
- Office sounds (off by default, speaker button at the top): synthesized in the browser, no audio files. A soft bell when a run finishes, a low buzzer when tests fail, a rising arpeggio when they pass, a ping when someone waits for permission, a paper rustle on hand-offs and quiet keyboard ticks while the team you are looking at writes.
- Payroll on the wall: a board above the reviewer's desk shows what each member cost this week (Monday onwards). Click it for the payslip and the cost per requirement item: a run's cost is split between the items it named, set or verified (R-046: $4.10, 2 runs, developer + tester).
- Posters on the back wall say what the project is built with (Angular, .NET, Godot, React Native, Node, PHP, Python, Docker…), detected from the project folder. Plain original designs, no logos.
- Broadcast: one button (camera icon by the zoom controls) turns the station into a live feed for a second screen. The interface steps aside, the camera glides by itself to whatever happens (a hand-off, a test run, a permission request, a run finishing or failing) with a lower third saying what it is, and in calm moments drifts from one busy room to the next. Record saves a 20 s clip of the 3D view as .webm, the camera button a picture. Esc leaves.
- Screensaver: left alone for four minutes with no conversation open, the station goes on air by itself (the broadcast above) and comes back at the first touch of the mouse or keyboard.
- Approval queue: an agent waiting for permission walks to the door with a "!" over its head; grant it (once or always) from the queue on the stage without opening the chat.
- Task board: agents leave a task for another role (or for you) instead of stopping at "I cannot do that"; start it with one click, track it in To do / In progress / Blocked / Done.
- Chat: team status strip, pinned last prompt; editor font zoom (Ctrl + wheel).
- Fixes: queued messages could get stuck after the agent finished; server restarts no longer silently cut agents off; notification panel overflow.

## 0.1.0 — first public release

- Isometric station: every project folder is a room, every role (developer, analyst, tester, reviewer) a character.
- Team workflow with hand-offs; only the developer writes files.
- Scope: requirements extracted from linked analysis documents, compared with code, verified by the tester with real evidence.
- Document coverage: every paragraph / item / row / heading / image tracked; "contains no requirement" needs your approval.
- Git checkpoints, change cards with diffs and one-click undo.
- Document library with version history, search, optional MarkItDown reader.
- English and Turkish UI.
- `npm run demo`: scripted demo agents on three sample projects, no Claude Code required.
