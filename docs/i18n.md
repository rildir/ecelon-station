# Translations (i18n)

English is the **source language**: every user-facing string in the code is written in English and
wrapped in `t("…")`. Other languages live in `public/i18n/<lang>.json`, which maps the English text to a
translation. A missing entry falls back to English, so a half-translated language still works.

```js
// browser (public/*.js)
import { t, locale } from "./i18n.js";
toast(t("Project removed"));
toast(t("{n} files changed", { n }));
new Date(x).toLocaleDateString(locale(), { day: "numeric", month: "short" });

// server (server/*.js)
import { t, locale, langName } from "./i18n.js";
res.status(400).json({ error: t("Agent is busy; stop it or wait for it to finish") });
```

Rules:

- The key is the English text itself, as a **plain string literal** (`t("…")`), never a template
  literal or a variable. Placeholders are `{name}`, filled from the second argument.
- Keep one sentence per key where practical; build longer messages from parts only when the parts
  are independent sentences. Do not split a sentence into fragments — word order differs by language.
- HTML in `public/index.html`: `<span data-i18n>Projects</span>` translates the text content;
  `data-i18n-attr="title,placeholder,aria-label"` translates those attributes. Both use the English
  text as the key.
- Server modules must not call `t()` at module top level (constants are evaluated once at import);
  put them in a function or getter so a language change takes effect without a restart.
- Locale-sensitive calls (`toLocaleDateString`, `toLocaleLowerCase`, `localeCompare`) take
  `locale()` instead of a hard-coded `"tr-TR"`/`"tr"`.
- Identifiers that cross a process boundary are English and never translated: MCP tool names and
  argument names, enum values in tool schemas, status codes (`todo`/`doing`/`done`), role ids,
  requirement codes (`R-001`), document section ids (`D1-004`).

The language is a user preference (`data/prefs.json` → `lang`, UI: the EN/TR button in the top bar).
Agents are told to answer in that language, and tool results shown in the chat use it too.

Check consistency (missing or stale entries, leftover Turkish text in code):

```
node scripts/i18n-check.mjs            # report
node scripts/i18n-check.mjs --strict   # exit 1 on problems (CI)
```

Adding a language: copy `public/i18n/tr.json` to `public/i18n/<lang>.json`, translate the values, add
the code to `LANGS` in `public/i18n.js` and `server/i18n.js`.
